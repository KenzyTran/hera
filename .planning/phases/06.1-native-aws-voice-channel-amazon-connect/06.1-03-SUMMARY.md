## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Lex V2 auto-creates FallbackIntent on locale create**
- **Found during:** Task 2 (first `terraform apply` attempt)
- **Issue:** `aws_lexv2models_intent.fallback` create failed with `ValidationException: Intent with name FallbackIntent already exists`. Cause: `aws_lexv2models_bot_locale.en_us` auto-includes built-in `AMAZON.FallbackIntent` immediately on locale create; Terraform's `aws_lexv2models_intent` then tries to CREATE it again.
- **Fix:** `terraform import 'module.aws_voice_channel.aws_lexv2models_intent.fallback' 'FALLBCKINT:EP8MNSCULA:DRAFT:en_US'` (intent_id is literal `FALLBCKINT` for built-in; format uses colons, not commas per AWS provider docs). Re-applied; in-place update applied (`fulfillment_code_hook { enabled = true }`) without conflict.
- **Files modified:** none (state-only import)
- **Verification:** Subsequent `terraform plan` showed `module.aws_voice_channel.aws_lexv2models_intent.fallback will be updated in-place` instead of create-with-conflict.
- **Committed in:** `5bc5f7f` (mentioned in body)

**2. [Rule 1 - Bug] Contact Flow ConnectParticipantWithLexBot requires three error transitions**
- **Found during:** Task 2 (second `terraform apply` after phone deferred)
- **Issue:** `aws_connect_contact_flow.hera_voice` create failed with `InvalidContactFlowException` and empty message body. AWS provider error didn't surface the underlying schema diagnostic.
- **Root cause investigation:** Tested minimal flow via CLI (success) then incrementally added Lex integration block via CLI (failure with verbose error). `aws --cli-error-format json` revealed: `problems[0].message = "Action is missing required error. Error: NoMatchingError, Path: Actions[2]"`. The Lex bot integration block requires THREE error transitions, not two: `InputTimeLimitExceeded` + `NoMatchingCondition` + `NoMatchingError`. Template had only the first two.
- **Fix:** Added `{ "NextAction": "play-error", "ErrorType": "NoMatchingError" }` to the `get-input` action's Errors array in `voice_flow.json.tftpl`. Re-applied successfully.
- **Files modified:** `infra/modules/aws_voice_channel/contact_flow/voice_flow.json.tftpl`
- **Verification:** `aws_connect_contact_flow.hera_voice` created with `Status=PUBLISHED`; `aws connect describe-contact-flow` confirms.
- **Committed in:** `5bc5f7f` (mentioned in body)

**3. [Rule 4 - Architectural] Phone number type changed DID -> TOLL_FREE then DEFERRED**
- **Found during:** Task 2 (first claim attempts)
- **Issue:** Module specced `type = "DID"`. DID pool in us-east-1 had hot churn — every `claim-phone-number` API call returned `InvalidParameterException: Phone number not available` for numbers that `search-available-phone-numbers` had just returned. Switched module to `type = "TOLL_FREE"` (functionally equivalent for inbound-only demo; both fit AWS-NAT-01 acceptance "format +1XXXXXXXXXX" and stay in free tier). Toll-free first claim succeeded API-side (returned `PhoneNumberId`) but `describe-phone-number` 8 seconds later showed `Status: FAILED, Message: "The allowed limit for claimed phone numbers has been exceeded for your instance"` despite quota (5/instance) and 0 phones actually claimed account-wide (`list-phone-numbers-v2` returns `[]`). Tried 3 different Toll-free numbers — same false-positive failure each time. Released ghosts (returned `ResourceNotFoundException`, self-cleaned).
- **Root cause (suspected):** AWS new-Connect-tenant eligibility gate. Fresh AWS accounts in us-east-1 hit a hidden warm-up requirement for Toll-free + DID claims; AWS Support ticket is the documented unblock path.
- **Fix:** Operator-approved deferral (user chose "Defer phone + complete partial" via AskUserQuestion). Commented out `aws_connect_phone_number.us_did` resource block in `main.tf` + replaced output value with literal DEFERRED string in `outputs.tf`. Module main.tf retains commented resource block + 3-step re-enable procedure in comment header. AWS-NAT-01 marked `[~] PARTIAL` in REQUIREMENTS.md (instance live, phone deferred). AWS-NAT-05 marked `[~] DEFERRED` (CCP smoke depends on phone). RUNBOOK Phase 6.1 includes "Phone number blocker" unblock section with AWS Support ticket template.
- **User approval logged:** AskUserQuestion 2026-05-16 — user chose "Defer phone + complete partial" after live-tested options A (Console claim) failing identically to API.
- **Files modified:** `infra/modules/aws_voice_channel/main.tf`, `infra/modules/aws_voice_channel/outputs.tf`
- **Committed in:** `5bc5f7f`

## Issues Encountered

- **MSYS2 path mangling on `/aws/...` log group prefixes** (recurring from Plan 06.1-01) — `aws logs describe-log-groups` from Git Bash mangles leading `/` to `C:/Program Files/Git/aws/...`. Fixed by prefixing `MSYS2_ARG_CONV_EXCL='*'`.
- **Connect emergency admin user missing** — `identity_management_type = "CONNECT_MANAGED"` instance created via Terraform API has no users by default; AWS Console "Open Connect" redirects to login page asking for username/password. Workaround: `aws connect create-user` via CLI with Admin security profile + Basic Routing Profile (commands captured in RUNBOOK Phase 6.1 → CCP smoke section). User `hera-admin` created with strong demo-only password for this session.
- **Phone number ghosts** — failed claims return `PhoneNumberId` from API but never attach to instance; `describe-phone-number` shows them, but `release-phone-number` returns `ResourceNotFoundException`. Ghosts auto-clean on subsequent search/claim; no manual cleanup needed.
