## Implementation Decisions

(Numbering continues from Phase 6 D-67. Phase 6.1 starts at D-68.)

### Lex V2 intent shape (AWS-NAT-02)

- **D-68: Lex V2 bot uses AMAZON.FallbackIntent + Lambda reads `event.inputTranscript`.** The Lex bot `hera-product-lookup-prod` (us-east-1) has exactly one intent: `AMAZON.FallbackIntent` with Lambda fulfillment configured. Lambda extracts the caller's transcribed speech from `event.inputTranscript` (the Lex V2 V2 conversation log field populated by Connect's "Get Customer Input" block before the transfer-to-Lex hand-off). Resource count: `aws_lexv2models_bot` + `aws_lexv2models_bot_locale` (en_US) + `aws_lexv2models_intent` (fallback) + `aws_lexv2models_bot_version` + `aws_lexv2models_bot_alias` = 5 resources. The custom-intent + `AMAZON.FreeFormInput` slot alternative was rejected: adds 1-2 resources (slot + sample_utterances), and Lex may attempt slot-elicitation prompts ("What product?") that conflict with the demo's "any utterance routes to KB" semantic. SPEC.md wording "captures the spoken question as the slot" is reconciled at the Lambda layer (Lambda treats `inputTranscript` as the captured query). NLU confidence threshold left at Lex default; barge-in handled in Contact Flow not Lex (see D-69).

### Contact Flow caller UX (AWS-NAT-04)

- **D-69: Contact Flow shape = brand greeting + barge-in ON + single-attempt error → disconnect.** Contact Flow `hera-voice-flow-prod` (~6 blocks): (1) Set Voice block → Polly Neural Joanna en-US; (2) Play Prompt → exact text "Welcome to Hera Apple Store. How can I help?" (Polly TTS, ~3s); (3) Get Customer Input → transfers to Lex bot `hera-product-lookup-prod`, `Interruptible=true` (barge-in ON — caller can speak over Polly); (4) Play Prompt → `$.External.message` from Lex Lambda response (the KB-derived answer), `Interruptible=true`; (5) Disconnect. Error branch off block 3 (timeout ~5s of silence OR Lex/Lambda failure): Play Prompt "Sorry, I could not hear you. Please call back." → Disconnect (single attempt, no re-prompt loop). Slightly above SPEC's "4 blocks" estimate (the error branch is conditional, not extra primary-path blocks). Lex bot side does NOT confirm or re-prompt — keeps the conversation one-shot. Re-prompt-once alternative was rejected for demo simplicity: extra blocks + counter state would inflate Contact Flow JSON without improving the demo's storytelling.

### Cross-region KB IAM (AWS-NAT-03)

- **D-70: Lookup Lambda role attaches existing managed policy `hera-kb-retrieve-prod` (Phase 2 D-22 consumer pattern).** Module `aws_voice_channel/` does NOT create a new KB IAM policy. The Lambda's execution role `hera-voice-lookup-lambda-prod` is created by the module with: (a) trust policy assumed by `lambda.amazonaws.com` with `aws:SourceAccount` confused-deputy condition, (b) `aws_iam_role_policy_attachment` for the existing `module.kb_consumer_policy.policy_arn` (the `hera-kb-retrieve-prod` managed policy from Phase 2 — zero wildcards, scoped to KB ARN `arn:aws:bedrock:ap-northeast-1:851725411875:knowledge-base/BKXE19AH89`), (c) inline policy for own CloudWatch log group writes only. IAM is account-scoped so cross-region attach (us-east-1 Lambda → ap-northeast-1 KB) works natively. Consumer-pattern reuse keeps Phase 1+2+3+6.1 KB IAM consolidated in one policy — drift-free. Trade-off acknowledged: if Phase 2's `kb_consumer_policy/` module ever changes the policy body, Phase 6.1 Lambda inherits the change automatically (acceptable for a single-tenant demo). The new-inline-policy alternative was rejected to avoid duplicating IAM and to follow the consumer pattern Phase 3 already established for AgentCore.

### Phase 6 archive structure (AWS-NAT-06)

- **D-71: `git mv infra/modules/twilio_bridge/ infra/archive/twilio_bridge_phase6_partial/` full preservation + new README.md explaining D-56.** Executed as part of the cleanup wave AFTER `terraform destroy -target=module.twilio_bridge` succeeds AND AFTER `infra/envs/prod/main.tf` removes the `module "twilio_bridge" {}` block + `infra/envs/prod/variables.tf` removes `twilio_bridge_image_tag` and `twilio_auth_token_secret_arn` variables (so terraform no longer reads from the archived path).
