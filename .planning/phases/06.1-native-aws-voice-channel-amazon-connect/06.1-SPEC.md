# Phase 6.1: Native AWS Voice Channel — Amazon Connect — Specification

**Created:** 2026-05-16
**Ambiguity score:** 0.16 (gate: ≤ 0.20)
**Requirements:** 6 locked
**Supersedes:** Phase 6 (PARTIAL — App Runner + Twilio architecture defective per D-56 finding)

## Goal

A caller dialing the Hera Amazon Connect US DID (or hitting it via the CCP browser softphone) hears a Polly TTS response containing live Bedrock Knowledge Base data within 3 seconds of finishing the question "Do you have iPhone 13 Pro Max in stock?" — proving a fully AWS-native voice channel works end-to-end on Phase 1's existing KB without any third-party (Twilio) dependency.

## Background

**What exists today:**
- Phase 1 KB live: `BKXE19AH89` in `ap-northeast-1` (Apple catalog with stock data)
- Phase 1 IAM consumer policy: `hera-kb-retrieve-prod` (zero-wildcard `bedrock:Retrieve` scoped to KB ARN; reusable from `infra/modules/kb_consumer_policy/`)
- Phase 3 widget_presigner Lambda pattern: `infra/modules/widget_presigner/src/handler.py` (template for Lambda-talks-to-Bedrock shape, including SigV4 + IAM)
- Phase 6 partial state: bridge container code + offline tests + 8 leftover AWS resources (ECR, 2 IAM roles, log group, ASC, Secrets Manager secret) — Pattern A "App Runner bridge" architecture defunct (App Runner edge rejects inbound WS)
- AWS account 851725411875 has ZERO existing Amazon Connect instances

**What's broken / missing:**
- v2.0 PSTN ingress entirely absent — no working phone-channel-to-chatbot path. Phase 6's Twilio-bridge approach was retired due to:
  1. App Runner inbound WS limitation (D-56 architectural defect)
  2. User decision (2026-05-16) to drop Twilio entirely and pivot native AWS

**What this phase produces:**
- An Amazon Connect instance in `us-east-1` (free tier US/CA inbound voice)
- A US DID claimed under that instance (~$1/mo)
- A Lex V2 bot with one intent "ProductLookup" wired to a Lambda fulfillment hook
- A Lambda (Python) that calls Bedrock KB Retrieve (`bedrock:Retrieve` on `BKXE19AH89` cross-region) and formats the answer for Polly TTS
- A Connect Contact Flow that greets the caller, invokes the Lex bot, and plays the Polly answer
- A vi+en bilingual workshop chapter (Phase 7.1, separate phase) — out of scope for 6.1 system work but tracked in roadmap

## Requirements

1. **AWS-NAT-01 — Connect instance**: An Amazon Connect instance exists in `us-east-1` with one claimed US DID phone number, configured by Terraform.
   - Current: Zero Connect instances in account 851725411875
   - Target: `aws_connect_instance.hera` in a new `infra/modules/aws_voice_channel/` module + 1 `aws_connect_phone_number` (US DID) attached
   - Acceptance: `aws connect list-instances --region us-east-1` returns 1 instance with `InstanceAlias` matching `hera-voice-prod`; `aws connect list-phone-numbers-v2 --target-arn <instance-arn>` returns ≥ 1 US DID

2. **AWS-NAT-02 — Lex V2 bot with ProductLookup intent**: A Lex V2 bot wired to an `AMAZON.FallbackIntent` that always invokes the lookup Lambda, capturing the caller's spoken question as the slot.
   - Current: No Lex bot in account
   - Target: `aws_lexv2models_bot.product_lookup` + 1 intent + 1 fulfillment Lambda hook reference
   - Acceptance: `aws lexv2-models list-bots --region us-east-1` returns the bot; bot has 1 intent with Lambda fulfillment configured

3. **AWS-NAT-03 — Lookup Lambda (KB Retrieve cross-region)**: A Python Lambda invoked by Lex that calls Bedrock KB `Retrieve` cross-region (us-east-1 Lambda → ap-northeast-1 KB) and returns a single sentence answer.
   - Current: No such Lambda; widget_presigner Lambda is template only (it does SigV4 presign, not KB Retrieve)
   - Target: `infra/modules/aws_voice_channel/lambda/handler.py` reads slot text → `bedrock-agent-runtime:Retrieve` against `BKXE19AH89` in ap-northeast-1 → returns `{"messages":[{"contentType":"PlainText","content":"<one-sentence answer>"}]}` per Lex V2 fulfillment response shape
   - Acceptance: Lambda invoked with synthetic Lex event (slot = "iPhone 13 Pro Max in stock?") returns a response payload containing the substring "iPhone 13 Pro Max" + at least one of `{"in stock", "available", "out of stock", "stock"}`

4. **AWS-NAT-04 — Connect Contact Flow + Polly TTS**: A Contact Flow that greets the caller, transfers to Lex, and reads back the Lex response via Polly Neural TTS.
   - Current: No Contact Flow in account
   - Target: `aws_connect_contact_flow.hera_voice` JSON definition with 4 blocks: Set Voice (Polly Neural Joanna en-US) → Get Customer Input (transfer to Lex bot) → Play Prompt (`$.External.message` from Lex) → Disconnect
   - Acceptance: Contact Flow ARN attached to the claimed phone number; `aws connect describe-contact-flow --instance-id <id> --contact-flow-id <id>` returns Status=PUBLISHED

5. **AWS-NAT-05 — CCP smoke verification**: Operator opens the Connect CCP (browser softphone), dials the US DID, asks "Do you have iPhone 13 Pro Max in stock?" via mic, and hears a Polly response containing both "iPhone 13 Pro Max" and a stock-status word — within 3 seconds of finishing the question.
   - Current: No verification mechanism
   - Target: Documented operator paste-flow in `RUNBOOK.md` (new `## Phase 6.1` section): login Connect Console → CCP → dial → record stopwatch
   - Acceptance: Operator self-reports PASS in `06.1-HUMAN-UAT.md` (audio response heard, contains expected substrings, ≤ 5s end-of-question to first audio); FAIL paths for >5s latency or wrong answer trigger gap closure

6. **AWS-NAT-06 — Phase 6 cleanup absorbed into 6.1**: Plan in 6.1 destroys the leftover Twilio-bridge AWS resources from Phase 6 (ECR repo, 2 IAM roles, log group, ASC, Secrets Manager secret) before any new 6.1 resources land.
   - Current: 5 Phase 6 leftover resources still in account ($0-$0.40/mo idle)
   - Target: First task in 6.1 plan runs `terraform destroy -target=module.twilio_bridge` + `aws secretsmanager delete-secret --force-delete-without-recovery`; module directory `infra/modules/twilio_bridge/` archived under `infra/archive/twilio_bridge_phase6_partial/` (NOT deleted — keep for reference)
   - Acceptance: `aws apprunner list-services` and `aws ecr describe-repositories --repository-names hera-twilio-bridge` and `aws iam get-role --role-name hera-twilio-bridge-instance-prod` all return Resource-Not-Found / count=0

## Boundaries

**In scope:**
- Amazon Connect instance + 1 US DID + Contact Flow + Polly TTS playback
- Lex V2 bot (1 fulfillment intent that captures any utterance)
- Lookup Lambda (us-east-1, calls KB cross-region)
- IAM least-privilege for Lambda + Connect-Lex integration role + Connect-Polly use
- Terraform module `infra/modules/aws_voice_channel/` + root `infra/envs/prod/` extension
- CCP smoke test verification protocol in RUNBOOK
- Phase 6 leftover teardown (D-56-defect cleanup absorbed into 6.1 first task)
- Archive `infra/modules/twilio_bridge/` to `infra/archive/` (preserve reference, remove from active terraform state)

**Out of scope:**
- Bidi voice streaming with Bedrock Sonic — explicitly deferred (one-shot Q&A pattern chosen for cost + simplicity per Round 1 decision)
- Bedrock AgentCore Runtime usage — Phase 6.1 does NOT call AgentCore at all (Lex+Lambda+KB direct path; AgentCore stays untouched for v1 web widget)
- Twilio reuse — no third-party telephony; Twilio account, signature validation, Media Streams JSON envelope all dropped
- Workshop chapter authoring — Phase 7.1 (separate phase) writes the bilingual chapter; 6.1 is system-only
- Toll-free number — US DID only ($1/mo) for cheapest demo; toll-free deferred
- Multi-language conversation — English only, mirroring v1 chatbot persona constraint
- Multi-intent / multi-slot Lex bot — single fulfillment intent that captures one utterance (extending intents/slots is post-v2.0 backlog)
- KB rebuild — reuses existing `BKXE19AH89` from Phase 1 verbatim (no re-indexing)
- Cross-region KB replication — Lambda hops us-east-1 → ap-northeast-1 once per call; latency budget allows
- Connect outbound calls — inbound only
- Connect chat / task / email channels — voice only

**Phase 6 explicitly:** Phase 6 stays in ROADMAP as `[~] PARTIAL` for historical reference (D-56 finding documented in `06-04-SUMMARY.md`). Phase 6.1 supersedes it for v2.0 closure but does NOT delete its planning artifacts.

## Constraints

- **Region split:** Connect instance in `us-east-1` (only region with Connect free-tier US inbound voice); KB stays in `ap-northeast-1` (Phase 1 D-14 default region). Lambda runs in `us-east-1` and calls KB cross-region. Adds ~150-300ms latency budget; acceptable per AWS-NAT-05's 3-5s acceptance window.
- **Cost cap:** Connect free tier covers 10,000 minutes/year inbound voice (US/CA). US DID ~$1/mo. Polly Neural ~$16/1M chars (≪ $0.01/test call). KB Retrieve ~$0.0004/query. Phase 6.1 testing budget bounded by Phase 4 `hera-billing-prod` $5/day alarm (no new alarm needed).
- **No Twilio:** Hard exclusion — no `twilio` SDK, no `X-Twilio-Signature`, no Media Streams JSON envelope in any new code under Phase 6.1.
- **No Bedrock Sonic streaming:** Hard exclusion — Phase 6.1 uses `bedrock-agent-runtime:Retrieve` (sync REST call) only. No bidi WSS, no `InvokeModelWithBidirectionalStream`.
- **D-64 v1 unchanged carry-forward:** No edits under `agent/`, `cdk/`, `infra/modules/{knowledge_base,kb_consumer_policy,agentcore_iam,ecr,widget_hosting,widget_presigner,observability}/`, `frontend/`, `bin/cleanup-verify.sh`, `bin/push-image.sh`. v1 web widget at `https://dg0w939ktclw6.cloudfront.net` MUST continue to work after 6.1 deploy.
- **Terraform `~> 6.27`:** Stack-wide Terraform version pin (Phase 1 lock); `aws_connect_*` and `aws_lexv2models_*` resources require provider ≥ 5.x — already satisfied by 6.27.
- **Latest API mandate (AGENTS.md):** Use Lex V2 (NOT Lex V1 deprecated), Polly Neural voices (NOT standard), Connect Outbound API v2 if needed.
- **No emojis** in code, logs, or markdown content (CLAUDE.md mandate carry-forward).
- **uv exclusively** for Python (uv add, uv sync, uv run); never pip install (CLAUDE.md mandate carry-forward).
- **Atomic commits** scoped to plan id (`feat(06.1-NN)`, `fix(06.1-NN)`, `docs(06.1-NN)`).
