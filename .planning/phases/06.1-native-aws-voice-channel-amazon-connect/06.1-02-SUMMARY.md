## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fix terraform cycle in lambda.tf between lex_invoke permission and awscc_lex_bot_alias**

- **Found during:** Task 5 (`terraform validate` after root wiring)
- **Issue:** `terraform validate` reported: `Error: Cycle: module.aws_voice_channel.aws_lambda_permission.lex_invoke, module.aws_voice_channel.awscc_lex_bot_alias.prod`. Plan's lambda.tf had `aws_lambda_permission.lex_invoke.source_arn = "${awscc_lex_bot_alias.prod.arn}/*"` AND plan's lex.tf had `awscc_lex_bot_alias.prod` with `depends_on = [aws_lambda_function.lookup, aws_lambda_permission.lex_invoke]` (Pitfall 2 mitigation). The combination of (a) source_arn referencing the alias resource + (b) alias depends_on the permission resource is a Terraform graph cycle.
- **Root cause:** Pitfall 2 demands alias `depends_on permission` (alias can't be created before Lambda permission lets Lex invoke). Plan's pattern referenced the alias resource ARN in source_arn, which Terraform's dependency-detection caught as an edge in the other direction, creating the cycle.
- **Fix:** Changed `aws_lambda_permission.lex_invoke.source_arn` from `"${awscc_lex_bot_alias.prod.arn}/*"` to a constructed canonical pattern `"arn:aws:lex:us-east-1:${var.account_id}:bot-alias/${aws_lexv2models_bot.product_lookup.id}/*"` (matches the AWS docs pattern at docs.aws.amazon.com/lexv2/latest/dg/lambda-attach.html: `bot-alias/{BotId}/*`). The permission now scopes by bot, not alias resource. Pitfall 2 depends_on chain preserved.
- **Files modified:** `infra/modules/aws_voice_channel/lambda.tf`
- **Verification:** `terraform validate` returns `Success! The configuration is valid.`; `terraform plan` succeeds. Threat T-06.1-02-01 still mitigated because this Lex bot only ever has the single `prod` alias, so bot-scope = alias-scope in practice.
- **Committed in:** `eac6c00` (Task 5 commit; documented in commit body)

**2. [Rule 3 - Blocking] Add infra/modules/aws_voice_channel/build/ to .gitignore**

- **Found during:** Task 5 (`git status` post-`terraform plan`)
- **Issue:** `data.archive_file.lookup` writes `${path.module}/build/handler.zip` on every plan/apply. Without a gitignore entry, `git add` would stage `infra/modules/aws_voice_channel/build/handler.zip` (a generated binary).
- **Fix:** Added two lines to `.gitignore` mirroring the existing `infra/modules/widget_presigner/build/` pattern (Plan 03-04 Task 5a).
- **Files modified:** `.gitignore`
- **Verification:** `git status --short | grep aws_voice_channel/build` returns empty.
- **Committed in:** `eac6c00` (Task 5 commit; bundled with cycle fix + root wiring)
